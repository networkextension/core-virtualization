# Upstream FreeBSD patches (Apple Virtualization.framework guests)

Three independent patches against FreeBSD `main` (see `BASE`), produced from the `vz` work on .89
(`/Volumes/cross-buld/freebsd-upstream`, branches `up/*`). Together they let stock FreeBSD arm64
images boot and be provisioned under Apple's Virtualization.framework (VZ) — today stock GENERIC
spins at 200% CPU with no console, and nuageinit cannot read a read-only seed.

## Review notes (what reviewers will ask)

**Patch 2 (GIC).** Maps the distributor only when `madt->Version == ACPI_MADT_GIC_VERSION_NONE`,
reads GICD_PIDR2, unmaps. Unknown ARCH values keep the old behaviour (rejected). Mirrors Linux
`acpi_validate_gic_table`/`gic_acpi_parse_madt_distributor` handling of GIC_VERSION_NONE.

**Patch 3 (virtio_console consdev).**
- TX: console printf and tty output share the single out virtqueue; serialized by a spin mutex
  (`vtcon_cn_tx_mtx`) because `cnputc` can run with spin locks held. `vtcon_port_out()` polls the
  host to completion under it — a long tty write holds a spin lock with interrupts off. Alternative:
  chunk tty writes, or only take the lock for the console port (already the case).
- Panic/kdb: no lock, drain the queue then emit.
- RX: polled `cngetc` between `cngrab`/`cnungrab` (in-queue interrupt disabled); partially consumed
  buffers are requeued.
- Teardown: `cnremove()` then `free()`; `cn_*` methods check `vtcon_cn_port` and `FLAG_GONE`. A
  reviewer may want stronger ordering against a concurrent `cnputc` on another CPU.
- Only after attach — no early console (VZ exposes the virtio console only via PCI).
- Rebased over the 2026-10-03 VIRTIO_CONSOLE_F_SIZE / RESIZE changes; console registration happens
  before `vtcon_port_update_console_size()`.
