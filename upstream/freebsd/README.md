# Upstream FreeBSD patches (Apple Virtualization.framework guests)

Four independent patches against FreeBSD `main` (see `BASE`), made on .89
(`/Volumes/cross-buld/freebsd-upstream`, branches `up/*`). Together they let stock FreeBSD arm64
images boot, show a console and be provisioned under Apple's Virtualization.framework (VZ). Today
stock GENERIC spins at 200% CPU with no console, and nuageinit cannot read a read-only seed.

**Not submitted.** For XiangBo Kong to review and submit under his own name.

## Review round 1 → what changed

| Finding | Resolution |
|---|---|
| Patches 2/3 had author `networkextension <…privaterelay…>` | Re-authored; all `From:` = Signed-off-by. |
| GICv2 ACPI driver also claims `VERSION_NONE` | New `gic_acpi_dist_version()` (sys/arm/arm/gic_acpi.c, prototype in gic_common.h) used by **both** drivers. NONE + GICv3 redistributors in the MADT (GICR subtable, or GICC with a GICR base) → read GICD_PIDR2 → V3/V4, so only gic_v3 claims it. NONE without redistributors keeps the old GICv2 behaviour and is never read beyond the GICv2 frame (0xFE8 is GICD_INMIR on GICv3.3, so a v2-offset probe was rejected). On VZ `devinfo` shows a single `gic0` (v3.0) + `vgic0`. |
| `pmap_mapdev()` NULL check, nested declarations | Dropped / moved to the top (style(9)). |
| `cnungrab` leaves pending input stuck (`notify` kicks the host) | Pending used-ring input is delivered with `vtcon_port_in()` under the port lock (after kdb only via `mtx_trylock`). |
| `cngetc` races a live `vtcon_port_in()` | On a live system `cngrab` takes the port lock (waits out an in-flight handler; the handler cannot re-enable the interrupt) until `cnungrab`; nesting is counted (kern_cons does not). No lock in panic/kdb. |
| Behaviour change for existing users | Tunable `hw.vtcon.console_enable=0` (documented in virtio_console.4, new LOADER TUNABLES section). |
| `std.virt` change | Split into patch 4. |
| One VM exit per character | Measured: no visible boot-time cost (below). |
| Teardown use-after-free | `vtcon_cn_port` is now read under the TX spin mutex in the emit path and cleared under it in teardown, so no console write is in flight once it is NULL. |
| Leaked `cngetc` buffer on teardown | Freed in teardown. |
| `FLAG_CONSOLE` set without the lock | Set under the port lock; the redundant write is gone. |
| **Found while testing:** `boot_verbose` hung the boot | The console was registered inside `vtcon_attach()`, before the transport sets `DRIVER_OK`; the device processes no virtqueue until then, so any printf in that window waited forever. Registration moved to the `virtio_attach_completed` method (called by pci legacy/modern and mmio right after DRIVER_OK; if_vtnet uses the same hook). |

## Test evidence (2026-10-27, .93: Mac, macOS 14.0, polar-vmd/VZ, 2 vCPU / 2 GiB)

Kernel: `main` 73b3fb41e67a + patches 1–4, `KERNCONF=VZTEST` (= GENERIC + `nodevice virtio_gpu`,
local only), booting the official `FreeBSD-15.1-RELEASE-arm64-aarch64-BASIC-CLOUDINIT-ufs` root via a
boot disk (`build/freebsd/50-vz-boot-disk.sh`).

- Boot: `FreeBSD 16.0-CURRENT #2 up/vz-test2-n290366-650809e0ff35 … VZTEST`;
  `devinfo`: one `gic0 <ARM Generic Interrupt Controller v3.0>` (+ `vgic0`); `kern.console: gdb,V0.0,/ttyv0,gdb,`;
  kernel messages on the VZ serial port (91 lines normal, 133 with `boot_verbose`).
- `hw.vtcon.console_enable=0`: `kern.console: gdb,/ttyv0,gdb,`, serial port silent, `/dev/ttyV0.0` still a tty.
- Live polled input: `vfs.root.mountfrom=ufs:/dev/bogus` → `mountroot>` prompt on the virtio console;
  typing `ufs:/dev/gpt/rootfs` (polar-vmd `serial.in`) boots the system; afterwards getty on `ttyV0.0`
  receives and echoes input (`login: polar`), i.e. interrupt-driven input works after cn_ungrab.
- Boot → sshd reachable (s, 3 runs): no console (`nodevice virtio_console`) 11.5 10.3 8.9 ·
  console 10.3 10.2 10.3 · console + `boot_verbose` 10.3 10.2 9.0. No measurable cost from the
  per-character VM exit at this output volume.
- Without patch 2 the VZ MADT reports GIC Version 0, gic_v3 never attaches and the kernel panics
  ("No usable event timer found!"), invisibly without patch 3. Patches 2+3 on `releng/15.1` also boot
  the 15.1 image (`15.1-RELEASE-p6 … VZ`, in daily use by the Polar VM app).
- Patch 1 — official 15.1 image, seed (FAT, label CIDATA) attached read-only: stock rc.d/nuageinit
  fails (`mount_msdosfs: … Read-only file system`, then `error parsing nocloud meta-data`); patched:
  user, SSH key, hostname and write_files applied, empty nuageinit.log.

Not exercised: ddb/kdb input (break into the debugger and type), multiport devices with
`VIRTIO_CONSOLE_CONSOLE_PORT` (QEMU `virtconsole`), port hot-unplug teardown.
